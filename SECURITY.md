# Security policy

## Scope

Current maintained release: v1.1.x. Security-sensitive areas include file-path confinement, project initialization, publication scanning and handling of user research data. This Skill is an optional local workflow and is **not** a sandbox or safe execution boundary.

## Vulnerability reporting

If GitHub private vulnerability reporting is enabled for the repository, use **Security → Advisories → Report a vulnerability**. Do not open a public issue with exploit details, access tokens, unpublished work or user files. If private reporting is unavailable, request that the maintainer enable a private reporting channel *without sharing details publicly*.

No response-time or remediation deadline is guaranteed. Do not upload sensitive samples as proof of concept; use synthetic, minimal reproductions.
